## 先說結論再展開

我花了差不多一個小時把 RecursiveMAS 的論文、GitHub 原始碼和 HuggingFace 上的模型全部看了一遍。直覺來說，這是一個「概念很乾淨、實作也夠簡潔」的工作, 沒有堆砌太多花巧的技巧，而是從一個很基本的問題出發：

> 如果單一語言模型可以透過在潛空間中反覆迭代來深化推理能力（這就是所謂的 recursive language model），那多智能體系統為什麼不能做同樣的事？

這個問題聽起來簡單，但之前的研究幾乎沒有人認真去回答它。大家基本上就是把幾個 LLM 串成一條流水線，A 做完給 B、B 做完給 C……文字傳過去傳過來，每輪都要完整編碼和解碼，訓練的時候更是困難重重, 要同時更新所有模型參數？不現實。順序依賴的文字互動帶來巨大延遲？沒得逃。

RecursiveMAS 的做法是：把整個多智能體系統變成一個遞迴循環，讓它們在潛空間中反覆迭代、互相影響。不是「大家輪流說話」，而是「大家在腦子裡反覆琢磨彼此的思路」。

下面我把看到的所有東西整理出來，包含核心概念、架構設計、實驗結果、代碼實作細節，以及我自己的看法。

---

## 一、背景：多智能體系統的痛點在哪？

大語言模型單獨使用時有個很明顯的天花板, 能力有限、容易短視近利、探索解空間的效率也不夠高。2024年以後，業界開始把多個 LLM 包裝成不同的「智能體」（agents），讓它們分工合作來解決更複雜的任務。這就是多智能體系統（Multi-Agent System, MAS）的概念。

但現有的 MAS 架構有個根本性的問題：溝通方式太原始了。

A 智能體寫一段回答給 B 看，B 再回覆 A……這種文字中介的互動方式，帶來三個痛點：

1. 速度慢, 每個回合都要完整編碼 → 解碼 → 重新編碼，中間所有步驟都必須等文字生成完畢
2. 訓練困難, 要同時更新所有模型參數幾乎不可能（計算量太大），而順序依賴的文字互動又帶來巨大延遲
3. 資訊損耗, 文字只是潛空間表示的一個子集。把複雜的推理過程壓縮成文字再解讀，會丟失很多細微的語意

RecursiveMAS 想解決的就是這三個問題。它的核心洞見很直接：既然單一語言模型可以透過在潛空間中反覆迭代來深化推理（這就是 recursive language model, RLM），為什麼不能把同樣的原理套用到整個多智能體系統上？

## 二、核心架構：RecursiveLink 是什麼？

### 2.1 Inner RecursiveLink, 讓智能體學會「在腦子裡思考」

每個 LLM 智能體都配一個 Inner RecursiveLink。它的作用很簡單：把模型最後一層的隱藏狀態（hidden state）轉換回輸入嵌入空間，這樣模型就可以直接把「剛剛想到的東西」作為下一步的輸入，而不需要先把想法說出來再重新編碼。

結構上是一個兩層殘差投影模組：
```
h → [預先歸一化] → W₁ → GELU → W₂ → [殘差連接 + h]
```

W₁ 和 W₂ 是標準線性層，GELU 激活函數，殘差連接保留原始潛表示的語義。這樣網路就不需要從頭學起整個投影關係，只需要學習「分佈差異」的部分, 訓練會更穩定、更快。

### 2.2 Outer RecursiveLink, 橋接不同智能體

Outer Link 的任務是把一個智能體的輸出轉換成另一個智能體能理解的表示。因為不同的 LLM 有不同的隱藏維度（比如 Qwen3-1.7B 和 Llama3.2-1B 的 hidden size 就不一樣），所以 Outer Link 多了一個額外的線性層 W₃，負責把源嵌入空間映射到目標嵌入空間：

```
h_source → [W₃ 映射] → [預先歸一化] → W₁ → GELU → W₂ → 
    └─[殘差分支：W₃ 將源嵌入映射到目標嵌入空間]──┘
```

### 2.3 整個系統怎麼串起來？

```
[問題輸入] → Agent A₁ (Planner) 
              ↕ InnerLink: 產生潛思考
              ↓ OuterLink: 轉換表示
           → Agent A₂ (Critic)
              ↕ InnerLink: 反思與批判
              ↓ OuterLink: 轉換表示
           → Agent A₃ (Solver)
              ↕ InnerLink: 最終推理
              ↓ OuterLink: 迴圈閉合
           → [回到] Agent A₁ ← 開始第 r+1 輪遞迴
              ...
           → Agent Aₙ 解碼出最終文字答案
```

每一輪遞迴，所有智能體都在潛空間中迭代 refine 自己的表示。關鍵是：在最後一輪之前，整個系統完全在潛空間中協作，不產生任何文字輸出。只有最後一輪才由最終的智能體解碼出文字答案。

## 三、四種協作模式

RecursiveMAS 的設計哲學是「結構無關」（structure-agnostic）, 它不綁定任何特定的多智能體架構，可以適配多種協作模式。論文實作了四種代表性模式：

### 3.1 順序風格（Sequential Style）

最直覺的模式。三個智能體各司其職，形成一條處理鏈：

- Planner（規劃者）：分解問題、制定策略
- Critic（評論者）：批判和審視規劃的完整性  
- Solver（求解者）：根據前兩者的輸入產生最終答案

適合需要逐步推理的任務，比如數學證明或複雜的問題解決。這跟現在很多 MAS 框架用的模式類似，但 RecursiveMAS 讓它們在潛空間中反覆迭代，而不是一遍過。

### 3.2 混合風格（Mixture Style）

多個領域專家並行運作：

- Math Expert：專注數學推理
- Code Expert：專注程式碼生成  
- Science Expert：專注科學問題
- Summarizer：綜合所有專家的輸出生成最終答案

這個模式有意思的地方在於，它不是簡單地「選一個最好的專家」，而是讓不同領域的專家在潛空間中反覆交流、互相影響。實驗結果顯示，這種跨領域的遞迴互動能產生比單一專家更好的效果（+6.2%）。

### 3.3 知識蒸餾風格（Distillation Style）

大模型和小模型的搭配：

- Expert（專家）：能力強但速度慢的大模型
- Learner（學習者）：速度快但能力較弱的小模型

透過 RecursiveMAS，Expert 的「思考方式」被遞迴地蒸餾到 Learner 中。最終 Learner 能達到接近 Expert 的準確率，同時保持更快的生成速度（1.5× 加速）。

這比傳統知識蒸餒更有意義, 不是簡單模仿輸出結果，而是在潛空間中學習專家如何思考、如何推理。實驗顯示 Learner 準確率提升了 8.0%。

### 3.4 深思熟慮風格（Deliberation Style）

最接近人類討論的模式：

- Reflector（反思者）：內在思考的智能體
- Tool-Caller（工具呼叫者）：能使用外部工具（Python 執行、搜尋 API 等）

兩者反覆對話、批判、修正，直到達成共識。這個模式特別適合需要工具調用的複雜任務。實驗中 Tool-Caller 的準確率提升了 4.8%。

## 四、訓練方法：只訓練幾個 KB 的 Adapter

這部分是我最佩服的設計, 整個系統唯一需要訓練的就是 RecursiveLink，所有 LLM 參數全部凍結。

### 4.1 內迴圈訓練（Inner-Loop）

首先為每個智能體單獨訓練其 Inner RecursiveLink。目標很直接：讓智能體學會把自己的「潛空間思考」和輸入嵌入空間對齊。

具體做法是：把標準答案文字通過該智能體的嵌入層轉換成潛表示作為目標，然後訓練 Inner Link 使得模型在自回歸生成過程中產生的最後層隱藏狀態，能透過 Inner Link 映射到這個目標分布上（用 cosine similarity 作為損失函數）。

這讓每個智能體都學會了「在腦子裡思考」而不需要每次都把想法說出來。

### 4.2 外迴圈訓練（Outer-Loop）

內迴圈完成後，開始訓練 Outer Link。整個系統按照遞迴循環的結構展開 n 輪前向傳播。最後一輪產生文字預測後，計算交叉熵損失，梯度會沿着完整的遞迴路徑反向傳播, 這意味著每個 Outer Link 都能根據它對最終答案的全局貢獻獲得共享的信用分配（credit assignment）。

關鍵特點：
- 所有 LLM 參數凍結, 只訓練 RecursiveLink（每個只有幾千到幾萬個參數）
- 梯度沿完整遞迴路徑回溯, 系統級優化
- 共享信用分配, 每個連結都根據其全局貢獻學習

### 4.3 為什麼潛空間比文字好？（理論分析）

論文提供了兩項重要的理論分析：

運行複雜度分析：
- 文字型遞迴 MAS：每輪需要完整的編碼 → 解碼 → 重新編碼，時間複雜度包含 `m × |V| × d_h`（詞彙表大小通常數十萬）
- RecursiveMAS：潛空間轉換只需要 `m × d_h²`

由於 `d_h ≪ |V|`（隱藏維度遠小於詞彙表），RecursiveMAS 在架構上就有顯著的效率優勢。這個分析很直觀, 你不需要把每個中間步驟都寫成文字再讀一遍，直接在腦子裡處理就好。

梯度穩定性分析：
- 文字型遞迴：梯度在反向傳播過程中會迅速消失（gradient norm → 0）
- RecursiveMAS：由於連續潛空間表示的穩定性，梯度保持恆定接近 1 的水準

這意味著 RecursiveMAS 在訓練時能更有效地跨輪次傳遞學習信號。文字中介就像傳話遊戲, 說太多輪就忘光了，但潛空間的連續表示不會有這個問題。

## 五、實驗結果：數據說話

論文在九個基準測試上評估了 RecursiveMAS，涵蓋數學推理、科學與醫學任務、程式碼生成和搜尋問答四大領域。使用的模型家族包括 Qwen3/3.5、Llama-3、Gemma-3 和 Mistral, 跨越多個開源生態系統，不是只綁定單一模型的自嗨研究。

### 5.1 整體性能

| 指標 | 數值 |
|------|------|
| 相比最強基線的準確率提升 | **平均 +8.3%** |
| 推理速度提升 | **1.2× ~ 2.4×**（遞迴深度增加時更明顯） |
| Token 使用量減少 | **34.6% ~ 75.6%** |

這三個數字放在一起看才有意義：不僅做得更好，而且做得更快、更省。在實際部署中，這直接轉化為更低的成本和更快的回應時間。

### 5.2 遞迴深度的影響

這是個很有意思的趨勢, 遞迴輪次越多，性能越好：

- r=1 時相比文字型基線提升 8.1%
- r=2 時提升 19.6%  
- r=3 時提升 20.2%

而且更有趣的是「訓練遞迴 vs 推理遞迴」的擴展行為：在較少輪次訓練的系統上增加推理深度，性能依然會改善；而加深訓練深度則把整體性能前沿向上移動。這表明訓練和推理階段的遞迴具有互補效應, 訓練教會系統產生可 refine 的潛表示，推理遞迴則將這些學習轉化為實際的性能提升。

### 5.3 不同協作模式的表現

| 模式 | 相比單一智能體的改進 |
|------|---------------------|
| 順序風格（Sequential） | +8.1% ~ 20.2%（隨遞迴深度增加） |
| 混合風格（Mixture） | +6.2%（跨領域組合效果顯著） |
| 知識蒸餾（Distillation） | Learner 提升 8.0%，同時保持 1.5× 速度優勢 |
| 深思熟慮（Deliberation） | Tool-Caller 改進 4.8% |

特別值得注意的是知識蒸餾風格的結果：小模型透過 RecursiveMAS 學習大模型的「思考方式」後，不僅準確率提升了 8%，還保留了比大模型更快的生成速度。這比傳統知識蒸餾（只模仿輸出）更有意義, 它學會的是推理過程本身。

### 5.4 效率分析

推理時間加速：
- r=1：平均 1.2× 加速
- r=2：平均 1.9× 加速  
- r=3：平均 2.4× 加速

遞迴越深，RecursiveMAS 的相對優勢越大。因為文字型方法每輪都要完整解碼所有中間輸出的文字，而 RecursiveMAS 大部分互動都在潛空間中完成。這個趨勢跟理論分析完全吻合。

Token 使用量減少：
- r=1：減少 34.6%
- r=3：減少 75.6%

隨著遞迴次數增加，RecursiveMAS 的 token 效率優勢進一步擴大, 因為文字型方法每輪都要重新解碼和編碼所有中間文本。

## 六、代碼實作細節

從 GitHub 倉庫來看，RecursiveMAS 的實作相當清晰，沒有藏太多東西：

### 6.1 核心檔案結構

```
RecursiveMAS/
├── modeling.py                     # RecursiveLink 模組定義 + 模型加載邏輯
├── run.py                          # 推理執行器（argparse CLI）
├── prompts.py                      # 各種智能體角色的提示模板
├── inference_utils/
│   ├── inference_mas.py            # 順序風格的完整推理流程
│   ├── inference_mas_deliberation.py  # 深思熟慮風格
│   ├── inference_mas_distill.py    # 知識蒸餾風格
│   └── inference_mas_mixture.py    # 混合風格
├── dataset/                        # 本地數據集（如 medqa.json）
└── hf_resolver.py                  # HuggingFace 模型解析邏輯
```

### 6.2 使用方式

```bash
# 基本用法（順序風格 + MATH500 數據集）
python run.py --style sequential_light \
              --dataset math500 \
              --num_recursive_rounds 3 \
              --latent_length 48 \
              --batch_size 32
```

支援的 style：`sequential_light` / `sequential_scaled`、`mixture`、`distillation`、`deliberation`。

### 6.3 模型檢查點

所有智能體的角色專屬檢查點和 RecursiveLink 模組都已發布在 Hugging Face（https://huggingface.co/RecursiveMAS/models）。每個 collection 包含特定協作風格下各角色的完整配置（LLM + InnerLink + OuterLink），可以直接下載使用。

## 七、我的看法：這個工作好在哪裡？不好在哪裡？

### 7.1 好的地方

概念乾淨。沒有堆砌太多花巧的技巧，從一個很基本的問題出發, 「多智能體協作能不能像單一模型的遞迴計算那樣深化？」, 然後給出一個簡潔而有力的答案。這種工作通常比那些「把 A 方法套到 B 領域再加點 C 技巧」的研究更有長遠價值。

參數效率驚人。用幾千到幾萬個參數的 Adapter，就能讓整個多智能體系統的性能提升 8.3%, 這比微調任何一個單一的 LLM 都要划算得多。在當前 LLM 訓練成本極高的背景下，這種「四兩撥千斤」的思路非常有實用價值。

理論支撐紮實。不是純靠實驗數據說話，而是從運行複雜度和梯度穩定性兩個角度提供了嚴格的理論分析。這兩項分析都很直觀, 潛空間轉換確實比文字編解碼快得多，連續表示確實比離散文字更利於梯度傳播。這不是事後找理由，而是設計之初就考慮到的核心選擇。

結構無關的設計。不綁定特定的協作模式或模型家族，可以靈活組合不同的智能體和任務類型。這讓 RecursiveMAS 有潛力成為一個通用的多智能體優化框架，而不只是某個特定場景的解決方案。

### 7.2 值得注意的地方（或者說缺點）

完整訓練流程尚未公開。README 上明確標註 training data 和實現細節還在規劃中（☑️ 狀態）。這意味著我們無法完全復現論文的訓練結果，也看不到他們實際用了多少訓練數據、花了多長時間。目前只能看到推理代碼和已經訓練好的檢查點。

評估任務偏向推理密集型。九個基準中有七個是數學、科學或程式碼相關，搜尋問答只有兩個（HotpotQA 和 Bamboogle）。在對話、創意寫作、情感理解等領域的表現尚不清楚。如果 RecursiveMAS 只在推理密集型任務上有效，那它的實用範圍會受到限制。

遞迴深度的實際限制。實驗顯示 r=3 時效果最好，但更深層次的遞迴（r > 5）是否會帶來收益尚未測試。過深的遞迴可能導致「過度思考」（overthinking），反而降低效率。另外，每個遞迴輪次都意味著更多的推理時間, 在需要即時回應的場景中，r=3 可能已經太慢了。

異構智能體的兼容性依賴 RecursiveLink。不同模型之間的表示對齊效果取決於 Outer Link 的訓練品質。對於差異極大的模型（比如 transformer vs. Mamba，或者不同架構的 LLM），Outer Link 能否有效橋接還需要進一步驗證。

## 八、可能的應用場景

基於這個框架的特性，我認為以下領域可能特別適合 RecursiveMAS：

- 教育領域：多個 AI 教師角色（規劃者、輔導者、評估者）透過遞迴互動為學生提供更深入的指導。這跟我們之前研究過的「Socratic Reverse AI」和「Digital Apprenticeship」概念可以很好地結合。
  
- 醫療診斷輔助：不同領域的醫學專家智能體反覆討論病例，逐步 refine 診斷建議。GPQA-Diamond 上 13.0% 的提升已經展示了它在科學推理上的潛力。

- 程式碼開發流程：規劃、編碼、審查、測試等多個角色協作完成複雜的軟體工程任務。Distillation Style 可以幫助小模型學習大模型的程式碼思維模式。

- 跨領域研究輔助：數學、程式、實驗設計等不同領域的專家智能體共同分析和解決科研問題。Mixture Style 天然適合這種場景。

---

## 九、值得追蹤的方向

1. 完整訓練管道的開放, 作者承諾會釋出完整的訓練數據和實現細節，屆時可以進行更深入的復現研究。這會讓我們看到他們實際用了多少數據、花了多長時間訓練，以及是否能在不同任務上複製這些結果。

2. 遞迴深度的自動調整, 能否讓系統根據問題難度動態決定需要多少輪遞迴？簡單的問題可能 r=1 就夠了，複雜的問題才需要 r=3+。這可能進一步提升效率。

3. 與 RLHF/RLAIF 的結合, RecursiveMAS 目前使用 SFT 訓練，如果加入強化學習反饋（比如讓系統自己評估每一步推理的質量），可能會產生更強大的智能體協作能力。

4. 在真實教育場景中的應用測試, 考慮到這個框架的多角色協作特性，它在 AI 輔助教育和學習領域可能有獨特價值。值得設計實驗來驗證。
